# On-device speech runtimes for a Whisper replacement

Scope: local file transcription of short voice notes. Weights are downloaded by the app. Audio must not leave the device. Live captions are out of scope. Cloud ASR APIs are out of scope. Date of research: 2026-10-27.

The language set used below is: en, de, es, fr, it, pt, nl, pl, ru, uk, tr, ar, hi, ja, ko, zh, sv, da, nb, fi, cs, el, he, id, th, vi, ro, hu, ca, hr.

## Current state of whisper.cpp, WhisperKit, transformers.js, and faster-whisper

### Takeaway

whisper.cpp, WhisperKit, and faster-whisper still run Whisper-architecture models as their main product. whisper.cpp has added a separate NVIDIA Parakeet TDT example, so the repo is no longer Whisper-only, but that path is a different CLI and model file, not a drop-in Whisper model. Transformers.js still documents Whisper on ONNX Runtime Web, and community ONNX exports have added at least Granite Speech and Voxtral to the same runtime, so it is no longer Whisper-only either. None of the four is a general ASR runtime for arbitrary architectures.

### Cited Findings

- whisper.cpp’s README still describes the project as a C/C++ port of OpenAI Whisper, with the high-level implementation in `whisper.h` / `whisper.cpp` and the rest in ggml. Latest release listed on the repo page is v1.9.5 (6 Oct 2026). The app today is on 1.9.4, one release behind that tag. — [ggml-org/whisper.cpp](https://github.com/ggml-org/whisper.cpp)
- Documented whisper.cpp platforms for the Whisper implementation: macOS (Intel and Arm), iOS, Android, Java, Linux/FreeBSD, WebAssembly, Windows (MSVC and MinGW), Raspberry Pi, and Docker. An iPhone 13 example is linked as fully offline. Bindings include JavaScript and React Native (`whisper.rn`) for iOS and Android, plus an XCFramework for iOS, visionOS, tvOS, and macOS. Some examples are ported to WASM (`whisper.wasm`, `stream.wasm`, `command.wasm`). — [ggml-org/whisper.cpp](https://github.com/ggml-org/whisper.cpp)
- The model download table is Whisper checkpoints only: tiny and tiny.en 75 MiB, base and base.en 142 MiB, small and small.en 466 MiB, medium and medium.en 1.5 GiB, large-v1/v2/v3 2.9 GiB, large-v2-q5_0 and large-v3-q5_0 1.1 GiB, large-v3-turbo 1.5 GiB, large-v3-turbo-q5_0 547 MiB. Names without `.en` are multilingual. Quantization is integer ggml quantization of Whisper weights. — [whisper.cpp models README](https://github.com/ggml-org/whisper.cpp/tree/master/models)
- A separate example, `examples/parakeet-cli`, runs NVIDIA `parakeet-tdt-0.6b-v3` from a ggml file (`ggml-org/parakeet-GGUF`, `ggml-parakeet-tdt-0.6b-v3-f16.bin`), with `models/convert-parakeet-to-ggml.py`. The CLI flags are threads, model, file, GPU on/off, and segment printout. Support was added in PR #3735, merged to master on 16 Jun 2026. A GitHub comment that Parakeet is a `--decoding-parakeet` flag on a Whisper ggml file was called out in the same thread as incorrect. — [parakeet-cli README](https://github.com/ggml-org/whisper.cpp/blob/master/examples/parakeet-cli/README.md); [PR #3735 CI](https://github.com/ggml-org/whisper.cpp/actions/runs/27640088032); [discussion #3312](https://github.com/ggml-org/whisper.cpp/discussions/3312)
- WhisperKit (Argmax open-source Swift SDK, repo now `argmaxinc/argmax-oss-swift`) is “speech-to-text with OpenAI Whisper” on Core ML. Prerequisites to build: macOS 14+ and Xcode 16+. Models are downloaded from `argmaxinc/whisperkit-coreml`. Recommended multilingual model in the README is the compressed Large v3 Turbo variant `large-v3-v20240930_626MB`; `tiny` is recommended only for debugging. `whisperkittools` converts fine-tuned Whisper models to Core ML. The open-source kit does not list Android; the README points Android and extra model families at the commercial Argmax Pro SDK. — [Argmax OSS README](https://github.com/argmaxinc/argmax-oss-swift/blob/main/README.md)
- Transformers.js enables WebGPU by setting `device: 'webgpu'` on an ONNX Runtime Web pipeline. The documented ASR example loads `onnx-community/whisper-tiny.en`. The WebGPU Whisper demo loads `onnx-community/whisper-base` and states the download is about 200 MB, cached in the browser, with no audio sent to a server. — [transformers.js WebGPU guide](https://github.com/huggingface/transformers.js/blob/main/packages/transformers/docs/source/guides/webgpu.md); [webgpu-whisper example](https://github.com/huggingface/transformers.js/blob/v3/examples/webgpu-whisper/src/App.jsx)
- The same Transformers.js stack is used for non-Whisper graphs when an ONNX export exists. `onnx-community/granite-4.0-1b-speech-ONNX` documents `GraniteSpeechForConditionalGeneration` with `device: "webgpu"` and q4 weights, for English, French, German, Spanish, Portuguese, and Japanese. `onnx-community/Voxtral-Mini-3B-2507-ONNX` is tagged Transformers.js; the `onnx/` tree is listed at 36.4 GB. — [Granite 4.0 1B speech ONNX](https://huggingface.co/onnx-community/granite-4.0-1b-speech-ONNX); [Voxtral Mini 3B ONNX tree](https://huggingface.co/onnx-community/Voxtral-Mini-3B-2507-ONNX/tree/main/onnx)
- faster-whisper is a Python reimplementation of OpenAI Whisper on CTranslate2. The project README’s benchmark is desktop GPU only (large-v2, beam size 5): faster-whisper fp16 1m03s and 4525 MB VRAM, int8 59s and 2926 MB VRAM, versus openai/whisper fp16 2m23s and 4708 MB, for 13 minutes of audio. It does not document iOS, Android, or a browser build. — [SYSTRAN/faster-whisper](https://github.com/SYSTRAN/faster-whisper)

### Inferences

- Staying on the current three clients means three Whisper stacks, not one runtime: whisper.cpp (Android, and optionally iOS/WASM), WhisperKit (iOS Core ML), Transformers.js (browser ONNX). They can share Whisper weights only after each stack’s own conversion (ggml, Core ML, ONNX).
- faster-whisper is not a candidate for this app. It needs Python and CTranslate2, and its speed claims are NVIDIA-GPU figures.
- whisper.cpp 1.9.5’s Parakeet CLI does not replace the Whisper API the Android app already calls. Shipping it would be a second code path and a second weight format, and the published example is a desktop CLI.

### Gaps

- The Parakeet CLI README does not say whether `parakeet-cli` is built into the iOS, Android, or WASM examples. Mobile and browser support for that ggml Parakeet file was not confirmed.
- No official WhisperKit RTF table was in the README. Third-party generated docs that quote RAM and “RTF < 0.2” were not treated as Argmax’s numbers.
- Whether every language in the app’s set is still in current OpenAI Whisper checkpoints was not re-checked against the OpenAI model card in this pass. whisper.cpp only says non-`.en` models are multilingual and points upstream.

## Cross-platform stacks that can run non-Whisper ASR

### Takeaway

sherpa-onnx is the only stack found with published iOS, Android, and in-browser examples across several non-Whisper families (Zipformer, Paraformer, SenseVoice, NeMo/Parakeet, Canary, Moonshine, and also Whisper). ONNX Runtime itself is the shared engine under sherpa, Transformers.js, and direct mobile ORT, but mobile builds reject some quant ops that desktop ORT accepts. ExecuTorch, Core ML, MLX, and LiteRT/MediaPipe each have real on-device demos, but none was found shipping the same non-Whisper ASR model on iOS, Android, and the browser. NNAPI was not re-verified as a current production EP.

### Cited Findings

- sherpa-onnx is a C++ library on ONNX Runtime. The current docs index lists streaming and offline Zipformer transducers, Paraformer, NeMo transducers, non-streaming Canary, SenseVoice, and Qualcomm QNN builds for specific int8 models. Named checkpoints include `sherpa-onnx-sense-voice-zh-en-ja-ko-yue-2024-07-17-int8` and a 2025-09-09 refresh (Chinese, English, Japanese, Korean, Cantonese), and `sherpa-onnx-nemo-canary-180m-flash-en-es-de-fr-int8` (English, Spanish, German, French). — [sherpa-onnx docs](https://k2-fsa.github.io/sherpa/onnx/)
- The NeMo transducer page documents `sherpa-onnx-nemo-parakeet-tdt-0.6b-v3-int8`, converted from `nvidia/parakeet-tdt-0.6b-v3`, and a non-streaming-only unified 0.6B English model. — [NeMo transducer models](https://k2-fsa.github.io/sherpa/onnx/pretrained_models/offline-transducer/nemo-transducer-models.html)
- A React Native TurboModule on sherpa-onnx reports Android and iOS support and model types transducer (Zipformer), Paraformer, NeMo CTC, Whisper, WeNet CTC, and SenseVoice, with int8 preferred when present. — [react-native-sherpa-onnx-stt](https://github.com/XDcobra/react-native-sherpa-onnx-stt)
- sherpa’s own WASM VAD+ASR demos, as indexed from the upstream script, include Whisper tiny.en, Moonshine tiny (English), SenseVoice (Chinese, English, Japanese, Korean, Cantonese), Paraformer, and Zipformer. The WASM build uses Emscripten, a virtual filesystem, and `ALLOW_MEMORY_GROWTH`. — [sherpa-onnx WASM notes derived from `scripts/wasm/generate-vad-asr.py`](https://deepwiki.com/k2-fsa/sherpa-onnx/3.8-webassembly-api)
- Rust API examples in sherpa-onnx also wire Moonshine v2, FireRedASR CTC, Qwen3-ASR, and Parakeet TDT, including “simulated streaming” (VAD plus offline decode). — [sherpa-onnx rust-api-examples](https://github.com/k2-fsa/sherpa-onnx/tree/master/rust-api-examples)
- ONNX Runtime Mobile is not the same op set as desktop ORT. A Moonshine Tiny re-export documents that static int8 `ConvInteger` is not registered in ORT Mobile on iOS or Android and crashes session creation; the mobile graph uses `MatMulInteger` and `DynamicQuantizeLinear` instead. Stated minimums: iOS 17 with CPU or Core ML EP, Android API 26 with CPU or XNNPACK, macOS 14 with CPU or Core ML. Dynamic int8 encoder is 12 MB versus a 29 MB fp32 encoder. — [moonshine-tiny-onnx-mobile](https://huggingface.co/bitsydarel/moonshine-tiny-onnx-mobile)
- `onnx-asr-web` runs ONNX ASR in Node and the browser on `onnxruntime-web` 1.24 or newer. It lists Nvidia Parakeet, Canary, FastConformer, and Conformer, plus Whisper, GigaAM, and Kaldi icefall Zipformer. The browser snippet loads `istupakov/parakeet-tdt-0.6b-v3-onnx`. This is a browser/Node library, not an iOS or Android runtime. — [onnx-asr-web](https://github.com/SanderGi/onnx-asr-web)
- ExecuTorch is PyTorch’s edge runtime (export to a `.pte` file, XNNPACK delegate). A PyTorch case study (26 Oct 2026) exports multilingual NVIDIA Nemotron 3.5 streaming ASR and runs it on a Google Pixel 11, one thread pinned to a mid-core CPU, 1,120 ms chunks, on a 24.9 s recording. With Arm SME2, FP16 processing time fell from 9.79 s to 4.61 s (2.12×) and QC8W int8 from 5.20 s to 3.24 s (1.61×). Both are under the audio duration. The post does not show iOS or a browser runtime. — [PyTorch ExecuTorch streaming ASR](https://pytorch.org/blog/optimizing-streaming-speech-recognition-on-arm-edge-devices-with-executorch/)
- Core ML is the engine WhisperKit uses on Apple platforms. Argmax’s open-source speech-to-text kit is Whisper. Argmax Pro is advertised with Android and non-Whisper models, including a Parakeet v2 row in their comparison, but that SDK is commercial and not a published weight format the app can host itself. — [Argmax OSS README](https://github.com/argmaxinc/argmax-oss-swift/blob/main/README.md); [Argmax SpeechAnalyzer comparison](https://www.argmaxinc.com/blog/apple-and-argmax)
- MLX is documented by Kyutai as the on-device path for Kyutai STT on iPhone and Mac. The same page’s production path is a Rust websocket server on GPU (64 streams at RTF 3 on an L40S). No Android or browser runtime is in that doc. — [Kyutai STT](https://kyutai.org/stt); [delayed-streams-modeling README](https://github.com/kyutai-labs/delayed-streams-modeling/blob/main/README.md)
- LiteRT / MediaPipe, in the sources found, is a path for Gemma-class LLMs rather than a speech-model zoo. An Android sample runs `gemma-3n-E2B-it-int4.task` through the MediaPipe LLM Inference API, with audio as a multimodal input to the LLM, model downloaded outside the APK. Official API page: MediaPipe LLM Inference for Android. No iOS or browser ASR example for that `.task` file was in the sources. A separate Android write-up used a Whisper TFLite interpreter for STT and Gemma 3n for the language model, which is still Whisper for the transcript. — [MediaPipe LLM Inference Android](https://ai.google.dev/edge/mediapipe/solutions/genai/llm_inference/android); [on-device-gemma3-lm](https://github.com/DaniZakaria63/on-device-gemma3-lm)
- WebGPU versus WASM, for Transformers.js: the official guide uses `device: "webgpu"`. A 2026 implementation note says `navigator.gpu` is not enough; call `requestAdapter()` and fall back to `device: "wasm"` when it returns null. A browser library that wraps Transformers.js and a Parakeet runtime reports WebGPU in Chrome 113+, Firefox 141+, and Safari 18+. — [transformers.js WebGPU guide](https://github.com/huggingface/transformers.js/blob/main/packages/transformers/docs/source/guides/webgpu.md); [OpenReplay captions article](https://blog.openreplay.com/add-video-captions-ai-browser/); [browser-whisper](https://github.com/tanpreetjolly/browser-whisper)
- sherpa WASM demos found are CPU WebAssembly, not WebGPU. Hugging Face spaces are published for those builds. — [WASM model table](https://deepwiki.com/k2-fsa/sherpa-onnx/3.8-webassembly-api)

### Inferences

- For a non-Whisper model the app would actually ship, sherpa-onnx is the practical single integration: one C++ core, JNI on Android, an iOS build, and a WASM build for the web, with the model as ONNX files plus `tokens.txt`.
- “ONNX” is not one file that runs everywhere. A graph quantized for desktop ORT can fail on ORT Mobile (`ConvInteger`). Any ONNX replacement needs a mobile-op export, not just an `onnx/` folder on Hugging Face.
- ExecuTorch is a real Android CPU path in 2026, demonstrated on a flagship Pixel, but it is a per-model export. It does not remove the need for separate iOS (Core ML or MLX or whisper.cpp) and browser (ONNX/WASM) work.
- Core ML, MLX, and the Apple Speech framework are Apple-only. LiteRT-LM is an Android LLM path. None of them closes the web client.

### Gaps

- Current ONNX Runtime docs for the NNAPI execution provider versus XNNPACK, QNN, and Core ML EP were not re-fetched. NNAPI’s status as a production EP in 2026 is unverified here.
- No ExecuTorch ASR example for iOS or the browser was found. The Pixel 11 post does not name a public `.pte` the app can download, or the language list of that Nemotron checkpoint.
- sherpa QNN models in the docs index are Chinese (and one SenseVoice) builds for a specific Snapdragon part (SM8850). Whether those binaries run on the app’s Android device range was not checked.
- Binary-size cost of linking sherpa-onnx or ONNX Runtime into the three clients was not found in a primary README.

## One runtime on iOS, Android, and web for a model that beats Whisper on the full language set

### Takeaway

No. sherpa-onnx is the only runtime found with production-shaped iOS, Android, and browser builds for models other than Whisper, but every non-Whisper checkpoint it publishes covers a subset of the language list. Parakeet TDT 0.6B v3 is the widest high-quality one, and it is 25 European languages. It does not include Arabic, Hindi, Japanese, Korean, Chinese, Turkish, Hebrew, Indonesian, Thai, Vietnamese, Catalan, or Norwegian Bokmål. Whisper remains the only family with a documented on-device path on all three clients and coverage of that whole set.

### Cited Findings

- `nvidia/parakeet-tdt-0.6b-v3` is a 600M FastConformer-TDT model. Supported languages, from the model card: Bulgarian, Croatian, Czech, Danish, Dutch, English, Estonian, Finnish, French, German, Greek, Hungarian, Italian, Latvian, Lithuanian, Maltese, Polish, Portuguese, Romanian, Slovak, Slovenian, Spanish, Swedish, Russian, Ukrainian. It auto-detects language. License is CC-BY-4.0. The card’s own multilingual table (greedy transducer, punctuation and case removed) reports average WER 11.97% on FLEURS, 7.83% on MLS, and 11.98% on CoVoST, and 6.34% average on the English Hugging Face Open ASR leaderboard sets. The card also says the models are optimized for NVIDIA GPUs, lists Linux and NVIDIA GPU microarchitectures, and says at least 2 GB RAM to load. The same card documents a local GGUF path via NVIDIA NeMo-Speech.cpp (`parakeet-tdt-0.6b-v3.q8_0.gguf`). — [nvidia/parakeet-tdt-0.6b-v3](https://huggingface.co/nvidia/parakeet-tdt-0.6b-v3)
- Overlap with the app’s list is en, de, es, fr, it, pt, nl, pl, ru, uk, sv, da, fi, cs, el, ro, hu, hr. Missing from Parakeet v3: tr, ar, hi, ja, ko, zh, nb, he, id, th, vi, ca. — [nvidia/parakeet-tdt-0.6b-v3](https://huggingface.co/nvidia/parakeet-tdt-0.6b-v3)
- SenseVoice in sherpa is Chinese, English, Japanese, Korean, and Cantonese, not the European long tail. — [sherpa-onnx docs](https://k2-fsa.github.io/sherpa/onnx/)
- Canary 180M flash in sherpa is English, Spanish, German, and French. — [sherpa-onnx docs](https://k2-fsa.github.io/sherpa/onnx/)
- Moonshine Voice’s published streaming models are per language, not one multilingual net. The readme table lists English (tiny/small/medium streaming), plus Arabic, German, Japanese, Mandarin, Spanish, Tagalog, and Vietnamese at tiny and sometimes small. Korean and Ukrainian are older non-streaming checkpoints under a non-commercial community license. English medium streaming is 245M parameters with 6.65% WER on the Hugging Face Open ASR leaderboard, against 7.44% for Whisper Large v3 at 1.5B, as stated by the author. That leaderboard is the English one. — [Moonshine Voice models](https://moonshine-voice.readthedocs.io/en/stable/models/available-models/); [announcement](https://petewarden.com/2026/02/13/announcing-moonshine-voice/)
- Kyutai’s released STT models are `stt-1b-en_fr` (English and French) and `stt-2.6b-en` (English). — [Kyutai STT](https://kyutai.org/stt)
- Granite-4.0-1b-speech’s ONNX card lists six languages: English, French, German, Spanish, Portuguese, Japanese. — [granite-4.0-1b-speech-ONNX](https://huggingface.co/onnx-community/granite-4.0-1b-speech-ONNX)
- IBM’s October 2026 Granite Speech 5 note recommends `granite-speech-5.0-470m-turboctc` for on-device and links a WebGPU streaming demo, and `granite-speech-5.0-2b` for higher accuracy. The note does not claim the full language set above, and it does not show an iOS or Android API. — [Granite Speech 5 blog](https://huggingface.co/blog/ibm-granite/granite-speech-5)

### Inferences

- A single runtime across three clients is possible (sherpa-onnx, or whisper.cpp if Parakeet mobile/WASM is later confirmed). A single model that is better than Whisper on every language in the set is not, among the checkpoints that actually have mobile or browser builds.
- Mixing models per language (Parakeet for European languages, SenseVoice for zh/ja/ko, Moonshine or Whisper for the rest) would be a product decision, not a runtime limitation. It breaks one download, one quality bar, and one punctuation behavior. For short voice notes that can be any of those languages, that split is the consistency problem Whisper was avoiding.
- “Beats Whisper” citations that do exist are English (Moonshine 6.65% vs Whisper Large v3 7.44% on Open ASR; Parakeet v3 6.34% English average on the same style of sets) or European FLEURS averages reported by NVIDIA without a Whisper column in the text retrieved here. They do not transfer to Arabic, Hindi, Hebrew, Thai, or Chinese.

### Gaps

- No head-to-head of Parakeet v3 against Whisper Large v3 on the full FLEURS language set was pulled from the model card’s plot image. The card says a plot exists and that Latvian was excluded from a Seamless comparison. Numbers in the HTML table are Parakeet-only.
- NeMo-Speech.cpp was not checked for iOS, Android, or WASM. The model card only shows a local `nemo-speech transcribe` command.
- Qwen3-ASR is wired in sherpa’s Rust examples, but its language list and mobile model size were not fetched.

## Practical constraints: size, RAM, speed, WebGPU, store and browser policy

### Takeaway

The binding constraint for a phone is the weight file plus peak RAM, not the runtime binary. Quantized Whisper small/turbo and SenseVoice int8 sit in a few hundred megabytes; Parakeet 0.6B int8 is about 0.6–0.9 GB and wants more RAM than a 4 GB phone can comfortably give a backgrounded app. Published phone timings are sparse and easy to over-read: one mid-range Android RAM report for SenseVoice, one third-party short-clip iPhone comparison for Moonshine versus Whisper small, and one flagship Pixel timing for a different streaming model. WebGPU is a faster browser path where the adapter exists, with WASM as the fallback. No source found says the App Store or Play policy forbids downloading model weights; Apple’s own speech models are downloaded on first use.

### Cited Findings

- whisper.cpp download sizes (unquantized unless noted): tiny 75 MiB, base 142 MiB, small 466 MiB, medium 1.5 GiB, large-v3 2.9 GiB, large-v3-q5_0 1.1 GiB, large-v3-turbo 1.5 GiB, large-v3-turbo-q5_0 547 MiB. — [whisper.cpp models](https://github.com/ggml-org/whisper.cpp/tree/master/models)
- WhisperKit’s recommended multilingual Core ML build is the 626 MB compressed Large v3 Turbo. The open-source README does not publish RAM or RTF. — [Argmax OSS README](https://github.com/argmaxinc/argmax-oss-swift/blob/main/README.md)
- Argmax’s own 20 Jun 2025 comparison table, reproduced on their site: WhisperKit `openai/whisper-base.en` error 15.2 and speed factor 111; Apple SpeechTranscriber error 14.0 and speed factor 70; WhisperKit `openai/whisper-small.en` error 12.8 and speed factor 35; Argmax Pro `nvidia/parakeet-v2` error 11.7 and speed factor 359. The retrieved table does not name the device. Speed factor is their metric, higher meaning faster. — [Argmax blog](https://www.argmaxinc.com/blog/apple-and-argmax)
- SenseVoice int8 file size reported by a user on sherpa-onnx issue #4056: `model.int8.onnx` 239 MB (`csukuangfj/sherpa-onnx-sense-voice-zh-en-ja-ko-yue-2024-07-17`). On a Redmi Note 11 (4 GB RAM), they measured about 570–730 MB for the model, app peak about 708 MB on 7 s of audio and about 773 MB on 48 s. The same user measured a 253 MB Q8_0 GGUF build at about 354 MB (7 s) and 446 MB (48 s) with a ggml engine on the same phone. The maintainer replied that the ONNX RAM gap is ONNX Runtime’s behavior and closed the issue. — [sherpa-onnx #4056](https://github.com/k2-fsa/sherpa-onnx/issues/4056)
- Parakeet TDT 0.6B v3 int8 ONNX, as packaged by third parties for sherpa: encoder about 623 MB, decoder 12 MB, joiner 6 MB (about 641 MB total). A SmoothQuant int8 encoder is listed at 842 MB, with the publisher claiming stock int8 WER 40.4% versus SmoothQuant 11.3% versus fp16 10.2% on a 390 s clip. Those WER figures are the publisher’s, not NVIDIA’s. NVIDIA’s card says at least 2 GB RAM to load the NeMo model. — [basque sherpa export file table, same base graph](https://huggingface.co/xezpeleta/parakeet-tdt-0.6b-v3-basque-sherpa-onnx); [SmoothQuant card](https://huggingface.co/pantinor/parakeet-tdt-0.6b-v3-smoothquant); [NVIDIA card](https://huggingface.co/nvidia/parakeet-tdt-0.6b-v3)
- Moonshine Tiny dynamic-int8 mobile ONNX is about 31 MB total in that export (encoder int8 12 MB). The card says iOS 17+ and Android API 26+. — [moonshine-tiny-onnx-mobile](https://huggingface.co/bitsydarel/moonshine-tiny-onnx-mobile)
- A different Moonshine Tiny ONNX card author reports one measurement: Whisper small took 45.9 s to transcribe a 3.3 s question on an iPhone 14 Pro Max, versus “a fraction of a second” for their Moonshine graph. That is one device, one clip, and not a paper. The same card says Moonshine does not pad to a fixed 30 s window. — [moonshine-tiny-en-onnx](https://huggingface.co/vasyadeva/moonshine-tiny-en-onnx)
- Moonshine Voice (the official runtime) states CPU-only inference, no NPU or GPU dependency, with prebuilt pieces for iOS, Android, Python, macOS, Windows, Linux, and Raspberry Pi. — [announcement](https://petewarden.com/2026/02/13/announcing-moonshine-voice/)
- Pixel 11 / ExecuTorch numbers are in the previous section: a 24.9 s clip processed in 4.61 s (FP16, SME2 on) or 3.24 s (QC8W, SME2 on) on one mid-core thread. That phone is not a mid-range device, and the model is Nemotron 3.5 streaming, not Whisper or Parakeet. — [PyTorch blog](https://pytorch.org/blog/optimizing-streaming-speech-recognition-on-arm-edge-devices-with-executorch/)
- Browser Whisper base in the Transformers.js demo is about 200 MB and is cached after download. — [webgpu-whisper example](https://github.com/huggingface/transformers.js/blob/v3/examples/webgpu-whisper/src/App.jsx)
- A community Kyutai browser build (not Kyutai’s supported path) uses a 531 MB Q4 GGUF plus a 107 MB Mimi encoder, about 640 MB on first load, and requires Chrome or Edge 113+ with WebGPU and HTTPS. — [stt-1b-en_fr-q4_0-webgpu](https://huggingface.co/idle-intelligence/stt-1b-en_fr-q4_0-webgpu)
- Voxtral Mini 4B Realtime in a Rust/Burn browser project: Q4 GGUF about 2.5 GB, sharded under 512 MB because of browser `ArrayBuffer` limits. On an NVIDIA DGX Spark their native Q4 path did 16 s of audio in 6629 ms (RTF 0.416). The WASM figure in the same table is about 225 s (RTF about 14). — [voxtral-mini-realtime-rs](https://github.com/TrevorS/voxtral-mini-realtime-rs)
- Granite-4.0-1b-speech GGUF sizes from IBM: Q4_K_M 1.14 GB, Q5_K_M 1.32 GB, Q8_0 1.96 GB. The card requires llama.cpp build b9045. It does not report a phone run. — [granite-4.0-1b-speech-GGUF](https://huggingface.co/ibm-granite/granite-4.0-1b-speech-GGUF)
- Apple’s SpeechTranscriber models are not in the app binary. Argmax’s comparison says the system model is downloaded on first use and does not increase the app download. Fraze, citing Apple’s AssetInventory docs and the WWDC25 session, says transcription runs on device and the model download is the step that needs a network. — [Argmax blog](https://www.argmaxinc.com/blog/apple-and-argmax); [Fraze](https://getfraze.app/learn/apple-speechanalyzer)
- WhisperKit likewise downloads Core ML weights on first use rather than baking them into the binary. — [Argmax OSS README](https://github.com/argmaxinc/argmax-oss-swift/blob/main/README.md)

### Inferences

- For short voice notes, a 30 s Whisper encoder window still costs a full window of compute on tiny clips. That is the concrete reason a variable-length encoder (Moonshine, or a transducer that scales with audio length) can look much faster than Whisper small on a phone even when the parameter count is similar. The only phone number in hand is the iPhone 14 Pro Max anecdote above, so it should not be generalized.
- A 4 GB Android phone can load SenseVoice int8, but a peak near 700–800 MB is a large fraction of the device. Parakeet 0.6B int8 at ~640 MB of weights, with ONNX RAM often well above file size, is a poor fit for that class of phone if the SenseVoice issue generalizes. That generalization is not proven; the maintainer attributed the multiplier to ORT, which is the same runtime Parakeet-in-sherpa uses.
- WebGPU should be treated as an optional accelerator in the browser, with WASM as the path that actually covers Firefox-without-adapter and older Safari. sherpa’s browser demos do not need WebGPU, which makes them more predictable and slower.
- Downloading weights after install is already how WhisperKit and Apple’s own transcriber work. That is evidence the stores allow on-demand model downloads. It is not a legal review.

### Gaps

- No primary source in this pass states an iOS App Store or Play policy that blocks, or explicitly allows, third-party speech-model downloads. Absence of a ban in these docs is not a policy citation.
- Cross-origin isolation (COOP/COEP) as a requirement for multi-threaded ONNX Runtime Web / SharedArrayBuffer was not re-read from current ORT or Emscripten docs. sherpa’s WASM notes show memory growth and a virtual filesystem, but not the HTTP headers a production site must send.
- No mid-range-phone RTF was found for Whisper small, Whisper turbo q5, or Parakeet int8. The faster-whisper README numbers are a desktop GPU and 13 minutes of audio.
- ggml Parakeet f16 file size is not in the parakeet-cli README.
- Peak RAM for WhisperKit’s 626 MB model on an iPhone was not in the official README.

## Apple on-device speech APIs in 2026

### Takeaway

A third-party iOS app can transcribe on device with `SpeechTranscriber` (a module of `SpeechAnalyzer`) on iOS 26 and later, without shipping its own weights. The transcript is local; the language assets are downloaded from Apple. There is no fixed language list in the API: the app must ask the device. That set is smaller than Whisper’s, can change per OS version, and is not available on Android or the web. The Foundation Models framework is a language-model API, not a speech-to-text API, even where Apple describes dictation as a feature of a newer on-device model.

### Cited Findings

- Apple’s docs: `SpeechTranscriber` is “a speech-to-text transcription module that’s appropriate for normal conversation and general purposes.” Apps should check `isAvailable` or `supportedLocales`. `supportedLocales` includes locales that are not installed but can be downloaded, and is empty if the device does not support the transcriber. `installedLocales` is what is already on device. `supportedLocale(equivalentTo:)` maps an arbitrary locale onto a supported one, preferring an installed locale with the same language code and a different region, and the docs warn that can change spelling (“color” / “colour”). If the transcriber is unavailable, Apple points at `DictationTranscriber`. — [SpeechTranscriber](https://developer.apple.com/documentation/speech/speechtranscriber); [supportedLocales](https://developer.apple.com/documentation/speech/speechtranscriber/supportedlocales); [supportedLocale(equivalentTo:)](https://developer.apple.com/documentation/speech/speechtranscriber/supportedlocale(equivalentto:))
- `SpeechAnalyzer` is the session; modules attach to it. On iOS 26 the modules named by a React Native binding are `SpeechTranscriber` and `SpeechDetector` (voice activity). The binding passes an ISO 639-1 language code and says assets are requested when transcription starts. — [Callstack, 16 Oct 2026](https://www.callstack.com/blog/on-device-speech-transcription-with-apple-speechanalyzer)
- Ship window stated by third parties, consistent with the docs existing as a current Speech framework type: iOS 26 and macOS 26, introduced at WWDC 2025. Fraze says the same APIs are listed as new across the other 26 OS releases. Argmax’s table: iOS 26+ and macOS 26+, versus WhisperKit iOS 17+ and macOS 14+. — [Fraze](https://getfraze.app/learn/apple-speechanalyzer); [Argmax blog](https://www.argmaxinc.com/blog/apple-and-argmax)
- Argmax’s feature table for SpeechAnalyzer (their measurements): offline and real-time transcription, word timestamps, and VAD are present; speaker diarization and language detection are not; “languages supported” is given as 10; the model does not increase app download size; compute is “Neural Engine + CPU (Hardcoded)”. Their error rate for SpeechTranscriber on that benchmark was 14.0 versus 12.8 for Whisper small.en. — [Argmax blog](https://www.argmaxinc.com/blog/apple-and-argmax)
- A later Mac app write-up (1 Sep 2026, updated 27 Oct 2026) says their FLEURS-style run got Apple Speech results for English, German, French, Spanish, Italian, Brazilian Portuguese, Japanese, Korean, Chinese, Cantonese, and eleven South Asian languages. For those South Asian languages they report Latin-script output rather than the language’s own script. They also say the app only offers a language when the OS reports support, and that this is not the full list Whisper covers. This contradicts Argmax’s “10 languages” if both are read as the current set; Argmax’s table is from June 2025 and the OS has had further releases. — [Whisper Notes](https://whispernotes.app/blog/apple-speech-vs-whisper)
- Older `SFSpeechRecognizer` remains the pre-26 path. Fraze notes `requiresOnDeviceRecognition`, which keeps that older API on device and which Apple describes as less accurate. — [Fraze](https://getfraze.app/learn/apple-speechanalyzer)
- Foundation Models, from Apple’s research posts, is access to the on-device language model used by Apple Intelligence: text tasks (summarization, extraction, short dialog, tool use), later image understanding, guided generation. The 2025 update says the models are designed to support 15 languages; an arXiv HTML copy of the related report says 16. Neither document describes an API that accepts audio and returns a transcript. — [Apple ML Research, 2025 update](https://machinelearning.apple.com/research/apple-foundation-models-2025-updates); [arXiv HTML](https://arxiv.org/html/2507.13575v2)
- A 2026 Apple research post on the third-generation foundation models says AFM 3 Core Advanced, a 20B-parameter sparse on-device model, enables system features including “higher-accuracy dictation.” The WWDC26 Foundation Models session summary covers a new on-device language model, image inputs, Private Cloud Compute, and a `LanguageModel` protocol. It does not add a speech-to-text method to that framework. — [third-generation foundation models](https://machinelearning.apple.com/research/introducing-third-generation-of-apple-foundation-models); [WWDC26 session](https://developer.apple.com/videos/play/wwdc2026/241/)

### Inferences

- iOS-only use of `SpeechTranscriber`, with Android and web staying on a downloaded model, is technically viable and keeps iOS audio on device after the asset download. It is a poor fit if the product needs the same transcript behavior in every language. The app cannot pin the model version, cannot ship a missing language, and cannot know the language list until runtime.
- Privacy is better than a cloud API and weaker than a model the app vendors itself: the asset download is a request to Apple, and the OS can fall back to `DictationTranscriber` on older or unsupported devices. What that fallback sends off device was not established in the retrieved docs.
- Foundation Models should not be planned as the voice-note engine. Dictation quality being improved inside Apple’s on-device model does not mean a third-party app can call that model with an audio buffer.

### Gaps

- Apple does not publish the `supportedLocales` array in the documentation. The 10-language figure and the 21-config Mac experiment disagree, and neither is a device inventory for iOS 26.x in October 2026.
- Asset size per language was not taken from Apple. A secondary article’s “about 100 MB per language” is not used here.
- Whether `SpeechTranscriber` can run with no network after the asset is installed, including airplane mode on first launch of a language, is implied by Argmax’s “offline” row and by Fraze, but the asset-install failure mode is not documented in the pages retrieved.
- No source confirmed `SpeechTranscriber` on Android, the browser, or as something the app can vendor. It is an OS feature.

## Parakeet, Canary, Moonshine, SenseVoice, Kyutai, Voxtral, Granite Speech, Gemma 3n

### Takeaway

Moonshine and SenseVoice have the clearest on-device paths (sherpa-onnx and, for Moonshine, its own iOS/Android runtime), and they do not cover the language set. Parakeet and the small Canary have ONNX and sherpa paths, plus a new ggml CLI for Parakeet v3; they are European or four-language models, and the int8 Parakeet graph is large for a phone. Kyutai is official on Apple via MLX and on GPU servers via Rust, with only a community browser port. Voxtral’s browser experiments are multi-gigabyte. Granite has a real browser ONNX/WebGPU path for six languages and a GGUF, not a shown phone stack. Gemma 3n on device is a multimodal LLM on Android LiteRT, not a replacement ASR.

### Cited Findings

- **Parakeet TDT 0.6B v3.** 25 European languages, CC-BY-4.0, 600M FastConformer-TDT. NVIDIA documents NeMo, Transformers, and NeMo-Speech.cpp GGUF. Community/mobile paths that exist in docs: sherpa-onnx int8 transducer, `onnx-asr-web` in the browser, and whisper.cpp `parakeet-cli` ggml. Not a Whisper-architecture model. Missing tr, ar, hi, ja, ko, zh, nb, he, id, th, vi, ca from the app’s list. English Open ASR average on the card is 6.34%. — [model card](https://huggingface.co/nvidia/parakeet-tdt-0.6b-v3); [sherpa NeMo page](https://k2-fsa.github.io/sherpa/onnx/pretrained_models/offline-transducer/nemo-transducer-models.html); [parakeet-cli](https://github.com/ggml-org/whisper.cpp/blob/master/examples/parakeet-cli/README.md); [onnx-asr-web](https://github.com/SanderGi/onnx-asr-web)
- **Canary.** sherpa documents a non-streaming int8 export, `sherpa-onnx-nemo-canary-180m-flash-en-es-de-fr-int8`, for English, Spanish, German, and French. `onnx-asr-web` also lists Canary as a browser ONNX type. No iOS-specific Core ML Canary was found. — [sherpa-onnx docs](https://k2-fsa.github.io/sherpa/onnx/); [onnx-asr-web](https://github.com/SanderGi/onnx-asr-web)
- **Moonshine.** Official Moonshine Voice runtime: ONNX Runtime flatbuffers, CPU only, iOS and Android packages, streaming models at 34M / 123M / 245M for English, MIT. Author’s English leaderboard claim: 6.65% WER for the 245M streaming model versus 7.44% for Whisper Large v3. Other languages are separate checkpoints; Korean and Ukrainian non-streaming models are under a non-commercial community license. sherpa-onnx also ships Moonshine, including Android APKs and a browser WASM demo for English tiny, and simulated streaming. A third-party mobile ONNX export exists because stock static int8 uses ops missing from ORT Mobile. No official Moonshine browser runtime is in the launch post. — [models](https://moonshine-voice.readthedocs.io/en/stable/models/available-models/); [announcement](https://petewarden.com/2026/02/13/announcing-moonshine-voice/); [moonshine issue #116](https://github.com/moonshine-ai/moonshine/issues/116); [sherpa APK comment](https://github.com/moonshine-ai/moonshine/issues/116)
- **SenseVoice.** sherpa-onnx int8 checkpoints for Chinese, English, Japanese, Korean, and Cantonese, with a WASM demo and a Qualcomm QNN build for SM8850. The 2024-07-17 int8 file used in the RAM report is 239 MB and peaked around 700 MB on a Redmi Note 11. Not a general European or Arabic/Hindi model. — [sherpa docs](https://k2-fsa.github.io/sherpa/onnx/); [issue #4056](https://github.com/k2-fsa/sherpa-onnx/issues/4056)
- **Kyutai STT.** Official: PyTorch, Rust GPU server, and MLX for iPhone and Mac. Models are English+French (1B, 0.5 s delay) or English (2.6B, 2.5 s delay). A community WebGPU Q4 package is about 640 MB and is not the documented Kyutai path. No official Android build was found. — [Kyutai STT](https://kyutai.org/stt); [community WebGPU weights](https://huggingface.co/idle-intelligence/stt-1b-en_fr-q4_0-webgpu)
- **Voxtral.** The Transformers.js-tagged ONNX tree for Voxtral Mini 3B is 36.4 GB, which is not a phone or a normal browser download. A later Rust project runs Voxtral Mini 4B Realtime from Q4 GGUF (about 2.5 GB) in the browser with WASM and WebGPU, and reports browser WASM at about 14× slower than real time on 16 s of audio, versus RTF 0.416 for native Q4 on an NVIDIA DGX Spark. No iOS or Android path was found. — [ONNX tree](https://huggingface.co/onnx-community/Voxtral-Mini-3B-2507-ONNX/tree/main/onnx); [voxtral-mini-realtime-rs](https://github.com/TrevorS/voxtral-mini-realtime-rs)
- **Granite Speech.** `granite-4.0-1b-speech` has an ONNX export aimed at Transformers.js WebGPU (q4) for six languages, and a GGUF (Q4_K_M 1.14 GB) that requires llama.cpp b9045. IBM’s Oct 2026 post points at `granite-speech-5.0-470m-turboctc` for on-device speed and a WebGPU demo, and at a 2B model for accuracy, with support named for Transformers, vLLM, llama.cpp, and mlx-audio. A 3.3-2B ONNX export’s int8 decoder external data is 2.53 GB, which is not a phone model. No production iOS/Android sample was found. — [ONNX card](https://huggingface.co/onnx-community/granite-4.0-1b-speech-ONNX); [GGUF card](https://huggingface.co/ibm-granite/granite-4.0-1b-speech-GGUF); [Granite Speech 5](https://huggingface.co/blog/ibm-granite/granite-speech-5); [3.3-2B ONNX](https://huggingface.co/OpenVoiceOS/granite-speech-3.3-2b-onnx)
- **Gemma 3n.** Android samples run E2B int4 as a MediaPipe / LiteRT LLM `.task` file, with audio as one of the inputs to a multimodal model, not as a dedicated ASR graph with a language list. One GDE article quotes about 2 GB for an int4 2B-class Gemma 3n and token rates on CPU, Adreno GPU, and Hexagon QNN; those rates are for text generation, not transcription RTF. Not a browser or iOS ASR path in the sources used. — [MediaPipe LLM Inference](https://ai.google.dev/edge/mediapipe/solutions/genai/llm_inference/android); [GDE LiteRT article](https://medium.com/google-developer-experts/from-zero-to-hero-running-googles-gemma-3n-on-android-with-litert-qualcomm-qnn-4eaa38bbadd4)

### Inferences

- If the goal is “one new model, three clients, all of those languages,” none of these replaces Whisper. The honest on-device options that are actually packaged for phones are Moonshine (per language, English is the strong one), SenseVoice (CJK plus English), and Parakeet via sherpa (25 European languages, heavy).
- Parakeet is the only one of these that both (a) has published WER that looks competitive with large Whisper on European and English sets and (b) has three different local runtimes sketched (NeMo GGUF, sherpa ONNX, whisper.cpp ggml, plus browser ONNX). The missing languages and the ~0.6 GB int8 encoder are the reasons it is not a drop-in for this app’s voice notes.
- Kyutai, Voxtral, Granite 2B-class, and Gemma 3n are the wrong shape for a short note on a mid-range phone and a browser tab: either the language coverage is tiny, or the download is multiple gigabytes, or the runtime is a GPU server with an Apple-only side path.

### Gaps

- Canary 180M int8 file size and any phone RTF were not on the docs page retrieved.
- Moonshine Voice’s iOS/Android packages were announced by the author; the library’s minimum OS versions and binary size were not copied from the repo in this pass.
- Whether llama.cpp’s mobile ports can run `granite-4.0-1b-speech` GGUF, as opposed to desktop llama.cpp b9045, was not verified.
- No source here shows Gemma 3n WER against Whisper on the language set. Treating it as an ASR replacement would be an inference the docs do not support.
